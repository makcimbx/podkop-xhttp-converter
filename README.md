# Podkop XHTTP Converter

[Открыть конвертер](https://makcimbx.github.io/podkop-xhttp-converter/)

Форк [EikeiDev/vless-xtls-converter](https://github.com/EikeiDev/vless-xtls-converter): исходный интерфейс сохранён и дополнен, парсер переписан, добавлены проверки и тесты. Благодарность автору оригинала. В исходном репозитории на момент форка лицензия не указана; этот форк не приписывает оригиналу новую лицензию.

Преобразует **VLESS + XHTTP + REALITY/TLS/без TLS** в **один outbound-объект sing-box-extended** для поля **Podkop → Proxy → Outbound Config**. Это не полный конфиг sing-box и не способ добавить XHTTP в обычное ядро без поддержки этого транспорта.

## Использование

1. Вставьте `vless://…` с явным портом и `type=xhttp` (также распознаётся старое имя `splithttp`).
2. Выберите профиль, нажмите «Конвертировать».
3. Прочитайте предупреждения и список преобразований. При сообщениях о неперенесённых полях нельзя считать JSON эквивалентом исходной конфигурации.
4. Скопируйте JSON в Outbound Config или скачайте файл. Проверьте соединение на своём сервере перед заменой рабочего подключения.

**Точный перенос** (по умолчанию): сохраняет указанный mode и XMUX, не добавляет настройки производительности за пользователя. Явно сообщает о необходимых дополнениях: например, `x_padding_bytes=100-1000`, если отсутствует, и uTLS `chrome` для REALITY без `fp`. Это перенос поддерживаемых полей, не побайтовое преобразование всех возможностей Xray.

**Podkop / extended** — отдельный, добровольно включаемый профиль:

- Если `extra.xmux` отсутствует, добавляет профиль из примера extended:
  ```json
  {
    "max_concurrency": "16-32",
    "max_connections": 0,
    "c_max_reuse_times": 0,
    "h_max_request_times": "600-900",
    "h_max_reusable_secs": "1800-3000",
    "h_keep_alive_period": 0
  }
  ```
- Для **REALITY + mode=auto** выбирает `stream-one`. Сервер должен поддерживать этот режим. Явные `packet-up`, `stream-up`, `stream-one` не меняет.
- Не заменяет уже заданный `xmux`, даже `{}` или нулевые значения. Пустой объект отличается от отсутствующего: он отключает автоматическую подстановку лимитов ядром.

Это настройки мультиплексирования HTTP-потоков/соединений, **не число CPU-потоков**. Профиль не гарантирует рост скорости, обход ограничений провайдера или устранение обрывов.

## Исправления относительно оригинала

- `security=none` больше не превращается в включённый TLS.
- `extra` и ALPN декодируются один раз, а не повторно после `URLSearchParams`. Литеральные `%`, `%2F` и `+` сохраняются. Ошибка JSON останавливает конвертацию, а не удаляет все дополнительные настройки молча.
- XMUX сохраняет диапазоны, числа, явные нули и отрицательный `h_keep_alive_period`. Несовместимые положительные `max_connections` и `max_concurrency` отклоняются.
- Расширен перенос XHTTP-параметров: padding/header/placement/method, `noGRPCHeader`/`noSSEHeader`, лимиты POST, headers, session/seq/uplink, chunk size и session ID, XMUX. Поддерживаются camelCase Xray и соответствующие snake_case поля extended.
- Явные `extra.host/path/mode` имеют приоритет; переопределения отображаются.
- Не навязывает ALPN `h2,http/1.1` и не подставляет SNI в `host`: ядро использует собственные значения по умолчанию.
- Проверяет UUID, порт, REALITY public key/short ID, диапазоны, режимы и несовместимые параметры. Валидация чисел намеренно ограничена безопасным диапазоном 32-битного роутера.
- Неизвестные URL/extra/XMUX-поля показываются в предупреждениях. Повреждённое `extra` и неподдерживаемые критические настройки вызывают ошибку.
- Пользовательские данные выводятся как текст, не HTML. Изменение ссылки или профиля сбрасывает предыдущий результат, чтобы не скопировать устаревший JSON.

## Совместимость и ограничения

Схема и результаты `sing-box check` проверяются на двух фиксированных релизах:

- `shtorm-7/sing-box-extended v1.13.18-extended-2.6.5`
- `shtorm-7/sing-box-extended v1.14.0-extended-2.7.1`

В этих версиях отсутствие XMUX означает `max_concurrency=1`, а XHTTP `auto` не разрешается в REALITY `stream-one` так, как в Xray. Для других версий необходимо отдельно сверять поведение.

Источники: [структуры и валидация старой версии](https://github.com/shtorm-7/sing-box-extended/blob/v1.13.18-extended-2.6.5/option/v2ray_transport.go), [новой версии](https://github.com/shtorm-7/sing-box-extended/blob/v1.14.0-extended-2.7.1/option/v2ray_transport.go), [клиент и режимы](https://github.com/shtorm-7/sing-box-extended/blob/v1.13.18-extended-2.6.5/transport/v2rayxhttp/client.go), [пример с XMUX](https://github.com/shtorm-7/sing-box-extended/blob/v1.13.18-extended-2.6.5/examples/xhttp/client.json).

Пока **не поддерживаются**:
- Xray `downloadSettings` / отдельный `transport.download`: вложенные настройки имеют другую структуру; конвертация останавливается вместо их потери.
- Непустой VLESS `flow` (включая Vision), VLESS Encryption кроме `none`, другие транспорты.
- uTLS/REALITY поверх HTTP/3: конфликт отклоняется, ALPN не меняется молча.
- Произвольные серверные параметры Xray без подтверждённого соответствия в исходящем конфиге extended.

Прохождение `sing-box check` означает корректность локальной конфигурации для ядра, **не проверку доступности сервера, TLS-handshake или скорости**. Для тестов используются только вымышленные данные и документационные IP-адреса.

## Приватность

Конвертация выполняется в браузере. Нет аналитики, внешних шрифтов, библиотек, запросов конвертации, cookies или web storage. CSP запрещает сетевые запросы через `connect-src 'none'`. GitHub Pages получает обычные запросы загрузки статических файлов и видит IP посетителя, **но введённая VLESS-ссылка не передаётся сайтом**.

Ссылка и результат остаются в памяти вкладки. Буфер обмена и скачанный JSON содержат UUID и другие данные подключения: обращайтесь с ними как с секретами. «Очистить» удаляет ввод/результат из интерфейса, но не очищает системный буфер обмена, файлы, память браузера или его механизм восстановления вкладок. Расширения браузера находятся вне контроля сайта.

Можно скачать исходники и запустить локально без интернета:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
# Открыть http://127.0.0.1:8765
```

## Разработка и проверки

Сайт — статические `index.html`, `style.css`, `converter.js`, `app.js`, без сборки и npm-зависимостей.

```sh
npm test
node tests/engine-check.cjs /path/to/sing-box-2.6.5 /path/to/sing-box-2.7.1
python3 -m pip install playwright==1.62.0
python3 -m playwright install chromium
# При запущенном локальном HTTP-сервере:
python3 tests/browser-check.py http://127.0.0.1:8765
```

GitHub Actions запускает unit-тесты, проверку JSON двумя ядрами (архивы сверяются с фиксированными SHA-256), браузерные проверки и публикует GitHub Pages только после успешных проверок на `main`. Изменения веток и PR проходят те же тесты без публикации.
